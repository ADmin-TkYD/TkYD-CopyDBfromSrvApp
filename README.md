# Backup Queue Utility

Асинхронная консольная утилита на Python для автоматизации и последовательного контроля процесса создания бэкапов баз данных с последующим их архивированием (7z или ZIP). 

Программа отправляет управляющие команды внешнему сервису, отслеживает появление временных файлов-кандидатов (`.db-`/`.dbx`), дожидается завершения формирования финального бэкапа, сжимает его в архив с отметкой времени и обновляет интерактивную таблицу статусов в реальном времени.

## 🚀 Основные возможности

* **Последовательная обработка очередей:** Базы обрабатываются строго по очереди, чтобы снизить нагрузку на дисковую подсистему.
* **Асинхронный движок (`asyncio`):** Ожидание создания файлов реализовано неблокирующим образом с настраиваемыми интервалами опроса и таймаутами.
* **Умное отслеживание изменений (Фикс багов):** Система запоминает метки времени (`mtime`) и игнорирует старые файлы, предотвращая повторную архивацию прошлых бэкапов.
* **Гибкая архивация:** Автоматический поиск и использование архиватора `7-Zip` (с настраиваемым уровнем сжатия до `9`). При его отсутствии используется PowerShell (`Compress-Archive`) или встроенный модуль `shutil`.
* **Интерактивный UI:** Информативное отображение текущего статуса обработки каждой выбранной базы в виде псевдографической таблицы в консоли.
* **Автоматическое извлечение путей:** Способность парсить бинарный файл конфигурации `Sls_Serv.cpy` для автоматического определения корневой директории бэкапов.

## 📦 Архитектура проекта

Проект разбит на логические модули:
* **`app.py`** — Главная точка входа. Координирует инициализацию, парсит аргументы, загружает конфигурацию и управляет асинхронной очередью.
* **`backup_archiver.py`** — Ключевой компонент ядра. Отвечает за логику ожидания файлов (`.db-` / `.dbx`), поиск установленного `7z.exe` и непосредственное архивирование с удалением исходного файла.
* **`ui.py`** — Кроссплатформенный менеджер интерфейса. Реализует интерактивное меню выбора баз и отрисовку интерактивной таблицы мониторинга.
* **`cfg_reader.py`** — Парсер основного файла конфигурации баз `SLS_SERV.CFG` (в кодировке `CP866`).
* **`cmd_writer.py`** — Генератор управляющих бинарных файлов команд (`Z_Cmnd.tmp` и `ZMon$tor.tmp`) для взаимодействия с внешним сервисом.
* **`extractor.py`** — Модуль безопасного извлечения Windows-путей из бинарных структур файла `Sls_Serv.cpy`.
* **`config_loader.py` / `logging_setup.py`** — Вспомогательные модули для загрузки `config.ini` и глобальной настройки форматированного логирования.

## 🛠 Настройка конфигурации (`config.ini`)

Поведение утилиты кастомизируется через файл `config.ini`:

```ini
[Paths]
# Путь к рабочей директории конфигурации и tmp-файлов
base_dir = c:\SoftLand Systems\SLS-Serv
# Корень бэкапов (если пусто, извлекается автоматически из Sls_Serv.cpy)
backup_root = 

[Backup]
# Интервал опроса появления файла-кандидата (в секундах)
creation_retry_interval = 3
# Максимальное время ожидания начала создания бэкапа (0 — бесконечно)
creation_retry_timeout = 0
# Интервал опроса готовности финального .dbx (в секундах)
dbx_poll_interval = 2
# Максимальное время ожидания .dbx файла (0 — бесконечно)
dbx_wait_timeout = 0
# Искать базы в поддиректории вида USER/<ИМЯ_БАЗЫ>
search_in_user_subdir = true

[Archive]
# Использовать 7z при наличии в системе (иначе создается ZIP)
prefer_7z = true
# Уровень сжатия 7z (от 0 до 9)
seven_zip_compression = 9
# Куда сохранять архивы (если пусто — сохраняются рядом с исходным файлом)
archive_output_dir = 

[Logging]
level = INFO
# Путь к файлу лога (если пусто — вывод только в консоль)
file = 
```

## 💻 Использование и запуск

Запуск осуществляется через командную строку. Доступны интерактивный режим и полная автоматизация через передачу аргументов.

### Параметры запуска:
```bash
python app.py [-b BASE_DIR] [-n DB_NUMBER] [pos_db_number]
```
* `-b`, `--base-dir` — Переопределить путь к рабочей директории (где лежат конфигурации и создаются `.tmp` файлы команд).
* `-n`, `--db-number` — Список номеров баз для обработки через запятую (например, `-n "1,3,5"`) или ключевое слово `ALL`.
* `pos_db_number` — Позиционный аргумент, альтернатива параметру `-n`.

### Примеры команд:

1. **Интерактивный режим:**
   ```bash
   python app.py
   ```
   *Программа считает список доступных баз и предложит вам ввести номера через запятую или написать `ALL` прямо в консоли.*

2. **Запуск конкретных баз по номерам:**
   ```bash
   python app.py -n "1,2,4"
   ```

3. **Запуск всех обнаруженных баз:**
   ```bash
   python app.py ALL
   ```

4. **Запуск с явным указанием рабочей директории:**
   ```bash
   python app.py -b "D:\SoftLand\Active" -n "2"
   ```

## 📋 Требования к окружению
* **Python 3.8 или выше** (используется современный синтаксис `asyncio` и аннотации типов).
* **ОС:** Windows (оптимизировано под структуры каталогов SoftLand Systems и системные вызовы WinAPI для консоли), однако базовые функции сжатия и очистки экрана поддерживают кроссплатформенность.
* **Рекомендуется:** Установленный архиватор **7-Zip** (программа автоматически ищет его в переменной окружения `PATH`, а также в стандартных директориях `C:\Program Files` и `C:\Program Files (x86)`).
